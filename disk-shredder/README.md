# 数据粉碎

删掉的东西还能被找回来——删除只是把文件从目录里摘掉，数据本身还躺在原来的簇上。这个插件做的是「让删掉的数据读不出来」，分两种用法：

- **粉碎文件 / 目录**：覆写文件内容 → 随机改名 → 删除，用于「我现在要删的东西，别被人恢复」
- **覆写空闲空间**：把卷上所有空闲簇写一遍，用于「我之前已经删掉的东西，别被人恢复」

## 覆写到底做了什么

```
打开文件（读写）→ 按档位逐遍覆写（保持原大小）→ 每遍 Sync 落盘
  → 随机改名 N 次 → 删除
```

三条看着别扭、但改了就失效的规矩：

1. **覆写必须保持原文件大小。** 先截断再写，NTFS 会分配到新簇，旧簇里的原数据一个字节没动——那就白覆写了。
2. **每遍写完都 Sync。** 只写进页缓存不落盘，删除之后什么都没留下。
3. **删之前随机改名若干次。** NTFS 把文件名放在 MFT 记录里，覆写文件数据流清不掉它；改名会让这条记录里的名字被覆盖。

档位：

| 档位 | 遍次 | 说明 |
|---|---|---|
| 1 遍（推荐，默认） | 随机 | NIST SP 800-88 Clear 对现代盘就是一遍，够用 |
| 3 遍 | 0x00 → 0xFF → 随机 | 与 Windows `cipher /w` 完全一致，方便对得上口径 |
| 7 遍 | DoD 5220.22-M 写法 | 多出来的只是等待时间，不买额外安全性 |

## 空闲空间覆写与 cipher 的关系

微软的 `cipher /w:D:\` 是这件事的事实标准，我们抄它的**语义**，不拿它当后端：

| | cipher /w | 本插件 |
|---|---|---|
| 覆写范围 | 整个卷的空闲空间（你指定的目录只用来定位卷） | 同 |
| 遍次 | 固定 3 遍 | 1 / 3 遍可选 |
| 能否中断 | 微软文档原话：**一旦启动就无法停止** | 可中断，取消时清理临时文件 |
| 写到多满 | 吃到 0 | 留安全余量（默认 2 GB，可选 5/10 GB） |
| 文件系统 | 仅 NTFS | NTFS / FAT32 / exFAT 都行 |
| 进度 | 只有点状指示，没有百分比 | 实时百分比、速度、剩余时间 |

不拿它当后端的原因很实在：不可中断 + 没有进度 + 固定三遍（实测 950 GB 空闲跑了 12 小时），对带进度条的 GUI 来说这三条都是硬伤；而临时文件是我们自己建的，取消时能删干净——这是自研相对调 `cipher` 最大的价值。

## 必须知道的四个真相

工具不说清楚这几点，做出来就是「假安全」：

| 真相 | 后果 |
|---|---|
| SSD / NVMe / U 盘有 FTL 磨损均衡与 OP 保留区 | 覆写写到的是新物理块，旧数据可能仍留在原块里。真要擦净请走厂商 Secure Erase 或全盘加密后丢弃密钥 |
| NTFS 上小于约 900 字节的文件内容常驻 MFT 记录 | 覆写数据流未必擦得到它们（`cipher` 文档自己说的是 4 KB 以下） |
| 卷影副本 / 系统还原点 | 覆写之后旧版本仍活在影子副本里，需要另行 `vssadmin delete shadows` |
| Gutmann 35 遍是都市传说 | 现代盘一遍足够，多遍只增加耗时 |

插件会读卷的介质类型（SSD / 机械盘）并把对应提示摆在预览区；读不出来就显示「未知」并把风险照实说，不会默认乐观。

## 三道闸门

不可撤销的操作，靠「点个确定」是不够的：

1. **后端硬拒绝**：设备路径（`\\.\PhysicalDrive0`）、卷根（`C:\`）、系统目录（`C:\Windows` / `Program Files` / `$Recycle.Bin` …）、符号链接一律不处理
2. **强制输入确认**：粉碎必须输入 `DELETE`，覆写必须输入目标卷名（如 `D:`）；验证在后端做，前端弹窗拦不住的路径传错，这一道拦得住
3. **先预览再执行**：列出目标、文件数、字节数、实际写入量、预计耗时与全部风险提示；被拒绝的目标单独列出原因

## 不做的事

**不碰裸盘 / 整盘擦除。** 三点原因：权限模型里没有对应键（`filesystem` 是按路径白名单配的，`\\.\PhysicalDrive0` 不在它的语义里）；需要管理员且本机在线处理不了系统盘；SSD 上覆写本来就无效。真要清盘卖电脑，正确做法是系统自带的重置 + 全盘加密丢弃密钥，本插件只会给指引，不会给一把会走火的枪。

## 用法

- **粉碎**：添加文件 / 目录（也支持粘贴路径）→ 选档位 → 预览 → 输入 `DELETE` → 开始
- **覆写空闲空间**：选卷 → 选档位与保留余量 → 预览 → 输入卷名 → 开始；过程中可停止，已覆写的部分不会回滚
- 被占用的文件会明确报错（「文件被其他程序占用」），不会静默跳过

## 边界

- 权限只声明了 `filesystem`：不联网、不调外部进程、不改注册表
- 只动用户明确选择的目标；目录递归时不跟随符号链接与 junction，避免顺着链接跑到别处
- 介质判定依赖 Windows 的 `IOCTL_STORAGE_QUERY_PROPERTY`，部分 USB 硬盘盒 / RAID 卡会吞掉该 IOCTL，此时显示「未知」

## 开发

```bash
go test ./...                        # 覆写正确性 / 护栏 / 随机名的单测
go build -o disk-shredder.exe .
python build.py disk-shredder        # 打包（按 platforms 字段）
```

源码：`main.go`（RPC 与命令分发）、`volume*.go`（卷枚举与介质判定）、`shred.go`（覆写粉碎）、`wipe.go`（空闲空间覆写）、`guard.go`（路径护栏）、`task.go`（任务会话）。
