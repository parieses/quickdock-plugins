# 局域网设备扫描

扫描你所在局域网里的在线设备，回答两个问题：**这个网里到底连了些什么**，以及**NAS / 打印机 / 摄像头到底分到了哪个 IP**。

打开即扫：自动挑一个本机私网网段（一般是 `/24`），并发探存活 → 扫端口 → 问主机名 → 认厂商，结果实时刷出来。

## 能拿到什么

| 字段 | 来源 | 说明 |
|---|---|---|
| IP | 网段展开 | 按 IP 数值排序 |
| 主机名 | NetBIOS（NBNS）→ mDNS | 两条路都问，都没答就留空 |
| MAC | ARP 缓存 / NBNS 回报 / 本机网卡 | 探测本身会把新设备写进系统 ARP 缓存，所以扫描结束时会再读一次 |
| 厂商 | 内置 OUI 表 | 手机开随机 MAC 时会注明「随机 MAC」，而不是留白 |
| 类型 | 端口 + 主机名 + 厂商推断 | 打印机 / 摄像头 / 群晖 NAS / iPhone / 网关等，猜不出显示「未知」 |
| 开放端口 | TCP 握手 | 带常见服务名（631 IPP、9100 打印、554 RTSP、5000 群晖…） |

## 存活是怎么判定的

这是插件能不能扫出东西的关键，值得说清楚：

- **握手成功** → 主机在线、端口开放
- **被拒绝（RST / ECONNREFUSED）** → **主机在线**、端口关闭
- **超时 / 不可达** → 没动静，不算在线

只看第一种的扫描器会漏掉大量设备——手机息屏、打印机待机、IoT 休眠时都不接受新连接，但它们的 TCP 栈仍然会回 RST。把「被拒绝」算作在线，才扫得全。

## 「仅 ARP 缓存」是什么意思

有些设备（尤其手机）连 TCP 都不回应，但只要最近通信过就一定留在系统的邻居缓存里。这些设备照样列出来，标上「仅 ARP 缓存」——缓存里也可能有已经关机的陈旧条目，所以如实标注，不混进「确认在线」里。

## 用法

- 网段：下拉自动列出本机所有私网网段，也可以手动填（如 `192.168.1.0/24`），最大支持 `/22`（1022 个地址）
- 端口：只探存活 / 常用 / 完整三档预设，也可以自己填（逗号分隔）
- 命令面板里输入 `192.168.1.0/24` 后调用本命令，会直接按该网段开扫
- 「复制 IP」按钮把 IP 写进系统剪贴板

## 边界

- **只读**：不发任何修改请求，不写文件，不改系统设置
- 只扫你自己的局域网：网段默认来自本机网卡，不跨网段、不做外网探测
- 主机名依赖对方开着 NetBIOS 或 mDNS，被防火墙拦掉时只能留空

## 开发

```bash
# 本地调试：在 QuickDock 插件管理页「从文件安装」本目录（需先压缩为 zip）
python build.py lan-scanner            # 打包
python gen_icons.py --gen lan-scanner  # 由 glyphs.py 的字形重新生成图标（需 Chrome）
```

后端命令（前端经 `plugin:execute` 调用）：`net-list` / `scan-start` / `scan-poll` / `scan-stop` / `clip-copy`。
