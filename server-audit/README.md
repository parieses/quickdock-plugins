# 服务器自查

> 对你自己的服务器做一次只读暴露面体检：解析预检 → 端口扫描 → 服务指纹 → 敏感路径 → 未授权校验 → 风险分级 → **加固对比**。

每天都在被别人扫的机器，需要的不是再装一个扫描器，而是**定期确认自己的暴露面有没有变多、改完的配置是否真的拦住了**。
本插件把这条链路串成一次点击：每轮自动留基线，加固后重跑直接给「已拦截 / 仍暴露 / 新增」。

- 运行时：`native`（Go，单文件可执行，无外部依赖）
- 分类：`安全工具`
- 权限：`network` + `filesystem`（仅 `~/.quickdock/plugin-data/io.github.parieses.server-audit/` 的读写，存基线）
- 窗口：900 × 600

## 做什么

| 阶段 | 动作 | 只读保障 |
| --- | --- | --- |
| 解析预检 | 域名 → A 记录，记录开始时间；可选 HTTP 查询 IP 归属（不查 whois） | 拒绝回环 / 内网 / 链路本地 / 组播 / 保留地址，防误扫他人内网 |
| 端口扫描 | TCP connect 两阶段：内置常用端口表（约 1100 个）→ 可选 1-65535 全量；输出开放/关闭/过滤三态 | 不用 ICMP、不用 raw socket、不做 SYN 半开（Windows 防火墙与杀软会拦） |
| 服务指纹 | TLS 优先（协议版本 / 套件 / ALPN + 证书 CN/SAN/颁发者/有效期/签名算法/密钥长度），失败回退 banner 抓取；再发 HTTP HEAD 与单次协议探测，归类 ssh/ftp/http/https/mysql/redis/mongodb/memcached/docker/es 等 | 探测指令只有 `HEAD`、`PING`、`version`、`isMaster`，不改目标状态 |
| 敏感路径 | 36 条内置路径只读 GET，随机路径基线 + 关键词佐证过滤 404 与软 404 兜底页 | 单次、不递归、不跟随跳转、正文最多读 1KB 作证据，并对口令字段打码 |
| 未授权校验 | Redis PING、Memcached version、Docker `/version`、ES `GET /`、FTP 匿名登录 | 每项**只做一次**，不分发字典、不并发认证、不重试 |
| 风险分级 | critical / high / medium / low / info，每条附处置建议，可导出纯文本报告 | — |
| 加固对比 | 每轮结果自动存为基线，修复后重跑按风险 ID 逐项比对，输出已拦截 / 仍暴露 / 新增 + 文本对比报告 | 只写本机 plugin-data；对比不向目标发任何新请求 |

## 验证修复有没有拦住

这是「不利用、不爆破」也能回答的问题——拦住的标志是**原来的风险点不再复现**，不需要真的把漏洞打通。

1. 跑一轮巡检（结果自动存为基线，每主机保留最近 6 条）。
2. 按报告里的处置建议改服务器配置：关端口、加认证、删备份文件、补 HSTS、换证书。
3. **重跑一轮**：插件自动与上一轮基线比对，概览页出现对比横幅，「加固对比」页列出三态明细。
   - 已拦截：`/.env` 从 200 变 401/403/404、Redis PING 从 `+PONG` 变 `NOAUTH`、端口从开放变关闭，都会落到这一类。
   - 仍暴露 / 加重：前后都在，或等级升高。
   - 新增：基线之后新出现的风险（只有完整重扫能发现）。
4. 只想快速看某一轮修好没：切到「加固对比」选基线，点**快速复验**——只对基线里的风险点各发一次只读请求（路径 GET、Redis PING、端口 connect、TLS 握手、HSTS 头），不重扫 65535 端口。

复验有 20 秒总预算；来不及复验的项一律按「仍暴露」保守计入，**绝不误报已拦截**。快速复验不发现新增风险，要完整结论请重扫。

## 明确不做

- 漏洞利用、上传 / 写入 / 删除任何内容、反弹 shell
- 多口令轮询同一账号（爆破）、字典喷洒、并发认证
- DoS / 压力测试 / 大量重复请求
- 下载或爬取目标业务数据、绕过认证、SQL 注入探测
- raw socket / SYN 扫描 / 伪造源 IP

## 命令

| 命令 | 说明 |
| --- | --- |
| `audit.start` | 发起巡检，返回 `sessionId`；参数 `host` 必填，另有 `mode`（common/full）、`ports`、`timeout`、`concurrency`、`checkPaths`、`checkUnauth`、`geo`、`compareWith`（指定基线，留空自动用上一轮） |
| `audit.poll` | 取阶段、进度、端口/指纹/路径/未授权/风险结果；结束后附 `comparison`（三态对比） |
| `audit.stop` | 中止会话（已扫到的结果保留） |
| `audit.report` | 导出纯文本报告 |
| `ip.lookup` | 查 IP 国家/地区、运营商与 ASN |
| `audit.baseline.list` / `save` / `delete` | 列出 / 手动保存 / 删除基线（正常巡检结束会自动保存） |
| `audit.compare` | 指定基线与某次已完成巡检对比；不传 `sessionId` 则走快速复验 |
| `audit.verify` | 快速复验：只针对基线风险点各发一次只读请求 |

默认参数：并发 500（硬上限 1000）、单端口超时 800ms、只扫公网目标（`allowPrivate` 不接受外部入参）。

基线文件：`~/.quickdock/plugin-data/io.github.parieses.server-audit/baselines.json`，
可用环境变量 `QUICKDOCK_PLUGIN_DATA` 改数据根（测试隔离用）。文件里存风险清单、开放端口与命中路径，
不含正文内容；路径证据在写入前已对口令字段打码。

## 调参取舍

- **并发 500 是默认，不是建议上限**：再高在笔记本上容易被本地 NAT / 光猫会话表压住，表现为大量 `filtered` 误判。上限硬编码 1000，改代码才能突破。
- **超时 800ms** 是「国内公网跨运营商」的经验值。丢包严重的线路可调到 1500，代价是全量扫描时间线性变长。
- **全端口**：65535 个端口在 500 并发下约 1~2 分钟；只扫常用表通常 3~8 秒。

## 开发

```bash
python build.py server-audit      # 打包（按 plugin.json 的 platforms）
go test ./...                     # 单元测试：预检拒绝、端口表、只读边界、基线落盘、三态对比、单次复验
```

本机若无 Chrome，`gen_icons.py --gen` 会失败（它靠 Chrome 量图形包围盒）。
图标目前是手写的规范形态，改字形请同步 `glyphs.py` 的 `GLYPH["server-audit"]`，
有 Chrome 的机器上跑 `python gen_icons.py --gen server-audit` 会重算包围盒与缩放。
